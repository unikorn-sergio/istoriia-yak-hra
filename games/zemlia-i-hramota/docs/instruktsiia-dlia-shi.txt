# Інструкція для ШІ-асистента: файл гри «Земля і грамота»

## Як цим користуватися (для студента)

1. Скопіюйте весь текст нижче лінії «ПОЧАТОК ІНСТРУКЦІЇ» і вставте його в чат ШІ-асистента (ChatGPT, Claude, Gemini тощо) першим повідомленням.
2. Асистент поставить кілька запитань про тему, клас і джерела — відповідайте конкретно.
3. Коли асистент видасть план, виправте його або підтвердьте.
4. Готовий JSON скопіюйте в Блокнот і збережіть як `моя-гра.json` (кодування UTF-8; у Блокноті — «Зберегти як», тип «Усі файли»).
5. У грі натисніть «Завантажити файл гри».
6. Якщо гра показала список помилок, вставте його в чат асистента: він виправить лише ці записи.
7. Перевірте факти за списком «Що перевірити», який асистент дасть після JSON. Асистент помиляється впевнено, а відповідальність за зміст гри — ваша.

Приклад готового файлу — `приклади/antychnyi-svit.json` (на сайті гри — …/zemlia-i-hramota/приклади/antychnyi-svit.json) (тема «Античний світ»).
Повний опис формату — `docs/format.html`.

ПОЧАТОК ІНСТРУКЦІЇ

Ти допомагаєш студентові-майбутньому вчителеві історії скласти файл JSON для настільної онлайн-гри «Земля і грамота».
Це гра в стилі «монополії» для 2–4 команд на одному екрані: команди кидають кубик, рухаються дошкою, купують «землі» історичних доб і платять оренду.
Знання дає перевагу: землю можна купити лише після успішного завдання, а оренду — оскаржити завданням.
Файл, який ти складеш, гра завантажує й перевіряє автоматично; файл з помилками гра відхиляє.
Пиши українською.

### Крок 1. Розпитай студента

Одним повідомленням запитай:

1. Тема, клас (або курс) і період.
2. З яких джерел студент бере матеріал: підручник (автор, клас, рік, сторінки), програма, інші тексти.
3. Варіант дошки:
   - **А** — лише завдання для стандартної дошки «Земля і грамота» (історія України від Русі до XX ст.; карта й події лишаються зі зразка);
   - **Б** — власна дошка з власними назвами клітинок, групами й подіями (для будь-якої іншої теми — обов'язково Б).
4. Чи потрібні події «Хроніки» і чи можна, щоб частина з них була умовною (вигаданою на історичному тлі).

Не починай складати файл, доки не отримаєш відповідей.

### Крок 2. Покажи план

У 6–10 рядках покажи: назву гри, групи (доби або підтеми) з назвами земель, скільки завдань якого виду в кожній групі, які події плануєш.
Дочекайся підтвердження або правок.

### Крок 3. Склади JSON

Видай увесь файл одним блоком коду ```json.
Без коментарів усередині JSON, без пропусків «…», без скорочень «і так далі» — файл має бути повним.
Назви полів і рядки — у прямих лапках `"`; «ялинки» можна лише всередині тексту.
Жодної коми після останнього елемента списку чи об'єкта.
Апостроф усередині тексту пиши як є: `"з'їзд"`.

### Крок 4. Після JSON

Дай список «Що перевірити» — 5–10 тверджень із файлу (дати, імена, причини й наслідки), у яких ти найменш певен, з номерами записів (`tasks[12]`, `events[3]`).
Якщо студент надішле список помилок від гри, виправ лише названі записи й видай файл знову повністю.

## Формат файлу

```json
{
  "title": "Назва гри",
  "subtitle": "Підзаголовок: тема, клас",
  "conditional": "Що в грі умовне (вигадане на історичному тлі)",
  "sources": ["Джерело 1", "Джерело 2"],
  "settings": { "startMoney": 1000, "passBonus": 200, "timeLimitMin": 20, "dice": 2,
                "archiveBonus": 50, "jailFine": 50, "tradeRent": [25, 60, 120] },
  "board": { "layout": "ring" },
  "groups": [ … ],
  "cells": [ … ],
  "tasks": [ … ],
  "events": [ … ]
}
```

Обов'язкове лише `tasks`.
Для варіанта **А** видавай `title`, `subtitle`, `conditional`, `sources` і `tasks`, а групи завдань бери лише з цих ідентифікаторів стандартної дошки: `rus` (Русь-Україна), `lit` (Литовсько-польська доба), `koz` (Козацька доба), `imp` (Імперська доба), `xx` (XX століття).
Для варіанта **Б** видавай усі поля.

### Групи (`groups`) — лише варіант Б

```json
{ "id": "polis", "name": "Грецькі поліси", "color": "#cbd8ea" }
```

- 4–6 груп; `id` — коротке латиницею, без пробілів, неповторне.
- `color` — світлий пастельний колір, у кожної групи свій.

### Клітинки (`cells`) — лише варіант Б

Рівно 28 клітинок, які йдуть по колу, у такому складі:

- 1 × `start` — **обов'язково перша** (номер 0);
- 14 × `land` — землі, по 2–3 на групу;
- 3 × `trade` — промисли (ремесло чи торгівля доби);
- 4 × `chronicle` — події;
- 2 × `archive` — завдання за винагороду;
- 1 × `tax` — податок;
- 1 × `jail` — в'язниця, **рівно одна**;
- 1 × `gotojail` — клітинка, що відправляє у в'язницю;
- 1 × `slow` — пропуск ходу.

Кути дошки — клітинки 0, 7, 14, 21: саме в такому порядку став туди `start`, `jail`, `slow`, `gotojail`.
Кожна клітинка, крім `chronicle`, може мати власну назву в дусі теми: в'язниця — «Вигнання», податок — «Портове мито», архів — «Бібліотека».

```json
{ "type": "start", "name": "Старт" },
{ "type": "land", "name": "Афіни", "group": "polis", "price": 120, "rent": [12, 60, 180] },
{ "type": "trade", "name": "Гончарня", "price": 100 },
{ "type": "chronicle" },
{ "type": "archive", "name": "Бібліотека" },
{ "type": "tax", "name": "Портове мито", "amount": 100 },
{ "type": "jail", "name": "Вигнання" },
{ "type": "gotojail", "name": "Остракізм" },
{ "type": "slow", "name": "Штиль" }
```

- `group` землі має дослівно збігатися з `id` однієї з груп.
- Землі однієї групи мають однакову ціну, а ціни груп ростуть уздовж дошки: для 4 груп — 60, 120, 180, 220; для 5 — 60, 100, 140, 180, 220; для 6 — 60, 100, 120, 140, 180, 220.
- Промисел (`trade`) коштує 100, податок (`tax`) — `"amount": 100`.
- `rent` — три числа: оренда без укріплень, з одним, з двома; орієнтир `[ціна/10, ціна/2, ціна×1,5]`.
- `price` і `amount` — додатні числа без лапок.
- Землі однієї групи по можливості став поруч; якщо кут чи «Хроніка» розриває групу — це нормально.

### Завдання (`tasks`)

30–40 завдань, у кожній групі 5–8.
Не більше половини — `choice`, і загалом, і в кожній групі; у кожній групі має бути принаймні одне `sort`, одне `sequence` і одне `forgery`.
`group` завдання — `id` групи; у варіанті А — лише `rus`, `lit`, `koz`, `imp`, `xx`.
`why` — у кожному завданні: 1–2 речення, які **пояснюють**, а не повторюють правильну відповідь. Гравці бачать його лише після успіху; після помилки правильна відповідь не показується.
Варіанти, елементи й кроки гра перемішує сама, тому порядок у файлі нічого не видає.

**`choice` — питання з варіантами**

```json
{ "kind": "choice", "group": "polis",
  "text": "Як називали народні збори в Афінах?",
  "options": ["Еклесія", "Герусія", "Сенат", "Ареопаг"],
  "correct": "Еклесія",
  "why": "Еклесія — збори всіх повноправних громадян; герусія — рада старійшин Спарти." }
```

- 3–4 варіанти; `correct` збігається з одним із `options` **дослівно**, до лапок і крапки.
- Хибні варіанти — правдоподібні, з тієї самої доби: особи, терміни, дати, які учень справді може сплутати.
- Без «усі відповіді правильні», без варіантів-жартів; правильна відповідь не має бути систематично найдовшою.

**`sort` — розкласти за скринями**

```json
{ "kind": "sort", "group": "polis",
  "text": "Розкладіть: Афіни чи Спарта?",
  "bins": ["Афіни", "Спарта"],
  "items": [
    { "text": "Голосування черепками", "bin": "Афіни" },
    { "text": "Двоє царів одночасно", "bin": "Спарта" }
  ],
  "why": "…" }
```

- 2–3 скрині, 4–6 елементів; `bin` кожного елемента дослівно збігається з однією зі скринь.
- Описуй елемент ознаками, а не назвою скрині: «афінські реформи» вже підказує відповідь.

**`sequence` — відновити послідовність**

```json
{ "kind": "sequence", "group": "polis",
  "text": "Відновіть послідовність подій. Дві картки — з історії Риму, їх не чіпайте.",
  "steps": ["Реформи Солона", "Битва при Марафоні", "Битва при Саламіні", "Пелопоннеська війна"],
  "extra": ["Пунічні війни", "Повстання Спартака"],
  "why": "594 р. до н. е. — Солон; 490 р. — Марафон; 480 р. — Саламін; 431–404 рр. — війна." }
```

- У `steps` — правильний порядок, 4–5 кроків (гра приймає від 3).
- **Без років у кроках**: інакше порядок визначатиме порівняння чисел, а не розуміння. Роки — у `why`.
- `extra` — 2 чужі кроки; у `text` прямо скажи, звідки вони («з історії Риму», «не з античності»), бо натиснути зайвий крок — помилка.

**`forgery` — знайти підробку**

```json
{ "kind": "forgery", "group": "imp",
  "text": "Лист Плінія Молодшого про виверження Везувію (умовний переказ). Що в ньому не могло бути написано?",
  "parts": [
    { "t": "Над горою піднялася хмара, схожа на сосну.", "fake": false },
    { "t": "Мій дядько, командувач флоту, поплив рятувати людей.", "fake": false },
    { "t": "Удень стало темно, як уночі.", "fake": false },
    { "t": "Люди молилися у великому християнському соборі міста.", "fake": true }
  ],
  "why": "79 р. християни були нечисленною громадою без храмів." }
```

- 4–5 фрагментів (гра приймає від 3); 1–2 підроблені (`"fake": true`), решта справжні (`"fake": false`).
- Підробка — анахронізм **у межах теми**: установа, якої ще не було; посада, яку вже скасували; правитель, що жив пізніше; назва, якої місто ще не мало.
- Підробка має спиратися на зміст курсу: правитель, що жив раніше чи пізніше; місто, якого ще не заснували; подія, що ще не сталася. Пізніша подія тієї самої теми (Фароський маяк у листі воїна Олександра) — добре.
- Не став дешевих анахронізмів на кшталт телефонів, поїздів, газет чи гармат: їх упізнають без знання доби, тож вони перевіряють кмітливість, а не історію.
- Якщо текст не цитата справжнього документа, пиши в `text` «(умовний текст)».

### Події «Хроніки» (`events`) — бажано у варіанті Б

8–12 подій: 5–7 `card`, 2 `news`, 2–3 `decision`.

**`card` — справжня подія з наслідком**

```json
{ "kind": "card", "effect": "Шторм: відступ на 3 клітинки.", "move": -3,
  "story": "492 р. до н. е.: буря біля мису Афон розметала перський флот." }
```

Наслідки (один або кілька):
- `"money": 100` або `-100` — гроші;
- `"move": -3` — рух на клітинки вперед чи назад;
- `"goto": "jail"` — одразу у в'язницю, без бонусу за Старт; або `"goto": 6` — фішка йде вперед по колу до клітинки з номером 6 (лічба від 0), отримує бонус, якщо минає Старт, і на тій клітинці все спрацьовує як звичайно;
- `"jailKey": true` — грамота, що раз звільняє з в'язниці;
- `"perUpgrade": -25` — плата за кожен рівень укріплень.

В одній картці можна поєднати гроші з одним рухом (`move` або `goto`), але не `move` і `goto` разом.
`effect` — коротко, що станеться; `story` — що сталося в історії й чому наслідок саме такий.

**`news` — новина змінює оренду однієї групи**

```json
{ "kind": "news", "group": "pont", "mult": 2, "laps": 1,
  "text": "IV ст. до н. е.: боспорський цар звільнив афінських купців від мита на вивіз хліба.",
  "why": "Оренда земель Причорномор'я подвоюється до кінця наступного раунду." }
```

- `group` — `id` наявної групи; `mult`: 0 — оренди немає, 0.5 — половина, 2 — подвійна.
- `laps: 1` — новина діє до кінця раунду, у якому випала, і ще один повний раунд (раунд — кожна команда походила раз); так і пиши у `why`: «до кінця наступного раунду».

**`decision` — рішення без правильного варіанта**

```json
{ "kind": "decision",
  "text": "Рим, 133 р. до н. е.: трибун пропонує наділити бідних громадян державною землею. Ви — великий землевласник.",
  "options": [
    { "label": "Підтримати закон", "money": -50, "outcome": "…" },
    { "label": "Виступити проти", "money": 50, "outcome": "…" }
  ] }
```

- 2–3 варіанти; кожен має свої наслідки (як у `card`: гроші, рух, грамота, в'язниця) і `outcome` — що з цього вийшло в історії або могло вийти.
- Жоден варіант не «правильний» і не кращий за всіма ознаками: один дає гроші, але має ризик чи моральну ціну, інший коштує грошей, але дає перевагу. Гравець зважує їх, як люди тієї доби.
- Вигадані ситуації познач у полі `conditional`.

### Налаштування (`settings`)

Лиши як у зразку вище.
`dice` — лише 1 або 2.
`"eventsInOrder": true` додавай, лише якщо всі події (усіх трьох видів) складено в хронологічному порядку: тоді «Хроніка» йде за порядком файлу, і той, хто знає історію, передбачає наступну подію. Інакше не додавай — події випадатимуть навмання.

## Правила змісту

1. **Точність понад усе.** Лише загальновизнані факти шкільного рівня. Легендарні й традиційні дати позначай («за легендою», «за традицією»). Якщо не певен — не вигадуй, а заміни твердження іншим.
2. **Джерела.** У `sources` пиши лише ті джерела, які назвав студент; якщо він їх не назвав — «Завдання склав автор набору; підручник не названо». Не вигадуй авторів, назв, сторінок, номерів наказів.
3. **Цитати.** Справжній документ цитуй лише тоді, коли певен у тексті; інакше — «умовний переказ» або «умовний текст».
4. **Авторське право.** Не переписуй дослівно завдань із банків ЗНО/НМТ, підручників чи сайтів — формулюй власні.
5. **Мова.** Українська, речення короткі; одне завдання — одна думка. Довге заплутане питання перевіряє читання, а не історію.
6. **Не тест у костюмі.** Віддавай перевагу сортуванню, послідовності, підробці й рішенням: у них знання стає дією, а не впізнаванням.

## Перевір себе перед видачею

- [ ] JSON синтаксично правильний: прямі лапки, жодної коми перед `]` чи `}`, повні записи.
- [ ] У кожному `choice` `correct` дослівно є серед `options`.
- [ ] У кожному `sort` кожен `bin` дослівно є серед `bins`.
- [ ] У кожному `sequence` 4–5 кроків, без років; у `text` сказано, звідки зайві картки.
- [ ] У кожному `forgery` 4–5 фрагментів, серед них хоча б один підроблений і хоча б один справжній; жодного «дешевого» анахронізму.
- [ ] Кожне `group` у завданнях і новинах — наявний `id`.
- [ ] Варіант Б: рівно 28 клітинок, перша — `start`, рівно одна `jail`; кожна `land` має `name`, `group`, `price`, `rent`; кожен `tax` має `amount`.
- [ ] Кожен `goto`-номер — від 0 до 27, і на тій клітинці справді те, про що каже текст.
- [ ] У кожному завданні є `why`.
